# NonDef Writing：替换与迁移规则

本规则与[620组词库](merged-replacements-620.md)配合使用。词库给出具体映射，规则处理同类的新写法。各词条的主要规则编号见[620组规则索引](replacement-rule-index.tsv)。

## 执行约定

1. 先执行SKILL.md的显式免责声明保护和六项总体约束，以下规则不能覆盖它们。只有文章实际存在明确的免责声明标题或标签，才保护对应部分并提醒；不按句意判断。
2. 对输入原文同时检查词条和规则。命中完整词条且语义、语法、证据状态适用时，使用原映射；未命中或映射不适用时，按下面的触发条件改写。没有词条命中也必须检查规则。
3. 一句话命中一个词条，不代表句中其他结构已处理；尚未覆盖的片段仍按规则检查。所有修改基于同一份输入原文决定，再统一生成结果，不对新生成文字反复套词条。
4. 规则适用于中英文；英文直接使用相应的英文结构，不把中文例子逐字翻译后强行套入。例子用于说明操作，不是新的强制替换表。
5. 只有触发条件成立且能保持原意时才改。无法从原文确定主体、指代、因果、完成状态或数量口径时，保留相应信息，不替作者推断或补造。

## R01 去掉不增加含义的动作包装

- **触发：** 一个动作外套了“进行、开展、予以、加以”等支持动词，或用名词短语绕述同一个动作。
- **改写：** 让实际动作直接充当谓语，保留时态、否定、对象和程度。
- **正例：** “对日志作了一轮核查”→“核查了日志”；“We carried out an examination of the logs.”→“We examined the logs.”
- **不改：** “实验正在进行”中的“进行”本身表达进展；“进行了三轮分析”不能丢掉“三轮”。

## R02 缩短冗长结构与时间、状态、条件外壳

- **触发：** “处于……状态”“在……的过程中／情况下”等外壳表达的内容可以用更短结构完整保留。
- **改写：** 改为直接的时间、状态或条件表达，不改变条件的强弱、范围和先后。
- **正例：** “等到缓存装满以后”→“缓存满后”；“During the period when the service is restarting”→“While the service is restarting”。
- **不改：** “只有校验通过才接收”不能改成一般的“如果校验通过”；状态尚在进行时，不能写成已完成。

## R03 保持逻辑关系，精简衔接

- **触发：** 多个连接成分重复表达同一关系，或衔接长于其承载的信息。
- **改写：** 保留一个准确的连接或直接衔接内容；因果、转折、递进、举例和条件不能互换。
- **正例：** “正是出于这个缘故，所以服务停止了”→“因此，服务停止了”；“For that reason, therefore, the service stopped.”→“Therefore, the service stopped.”
- **不改：** 对照两种不同条件所需的“而”仍应保留；不能为了顺畅把并列改成因果。

## R04 采用自然常用表达，保留术语

- **触发：** 冷僻、文言或生硬表达妨碍理解，原文存在语义等价的常用写法。
- **改写：** 按完整词义单位替换，保持学术语域、情态和指代。
- **正例：** “毋须再次录入”→“不必再次录入”；“prior to installation”→“before installation”。
- **不改：** 专名、引用原文和术语中的字词不拆换；“数据集”“显著性”“重要性采样”不能按普通同义词拆改。

## R05 直接陈述研究问题、目标与贡献

- **触发：** 作者用多层“所关注的、作为视角、希望探讨”等结构绕述同一个研究对象或目标。
- **改写：** 明确谁研究什么、想解决什么，或已经提出了什么；依原文保留目标、尝试和成果的区别。
- **正例：** “我们想弄清的，是拥塞从何处产生”→“我们研究拥塞的来源”；“The question we seek to answer is whether X affects Y.”→“We ask whether X affects Y.”
- **不改：** “计划开发、试图证明、尚未验证”不能改成“开发了、证明了、验证了”；不另加创新性或领先性。

## R06 删除不承载信息的提示语

- **触发：** 一段提示只是在宣布“下面我要说明”，删去后事实、解释和边界均完整。
- **改写：** 删除提示外壳，保留它引出的实质内容；必要时修复紧邻的语序和标点。
- **正例：** “这里还得插一句，样本来自同一所学校”→“样本来自同一所学校”；“We would like to point out that the sample was small.”→“The sample was small.”
- **不改：** 不能因为前缀冗余就删掉后面的来源、风险、例外或研究限制；显式免责声明部分不参与删改。

## R07 移除空泛的自我辩护与自我贬低

- **触发：** 作者只是在请求谅解、声明无意冒犯、预防评价，或贬低自己，没有补充问题、证据或实质边界。
- **改写：** 删除这类话；有具体研究信息时保留信息，直接陈述。
- **正例：** “列出这些差别绝无冒犯前人的意思。两组相差3 ms。”→“两组相差3 ms。”
- **不改：** “样本不足以支持总体推断”提供了证据边界，不能作为心虚表达删除；不把未标注文字认作免责声明。

## R08 用问题、动作或结果取代流水账

- **触发：** “先翻资料、又试了几次、最后才发现”等叙述只记录写作或研究经过，对解释结果没有作用。
- **改写：** 保留最终采用的方法、发现及必要步骤；只有真实的实验顺序、时序依赖或复现步骤才保留过程。
- **正例：** “看过几遍日志以后，我们才察觉重试次数上升”→“日志显示重试次数上升”。
- **不改：** “先划分训练集再拟合归一化参数”关系到数据泄漏，顺序必须保留；不能删除阴性或失败结果。

## R09 让方法、数据操作和来源更直接

- **触发：** 方法或操作被多层“借助……来完成……工作”包裹，数据来源和处理对象不清楚。
- **改写：** 用原文已有的主体和工具直接表达操作，明确原有来源、样本与变量关系。
- **正例：** “借助逐请求记录来完成重试次数的核算”→“用逐请求记录统计重试次数”。
- **不改：** 数据收集、清洗、标准化、归一化、训练、检验是不同操作，不能为替换而互换；没有主体就不编造主体。

## R10 准确陈述结果、指标与比较

- **触发：** 结果藏在“可以从……发现”的绕述中，或评价词代替了原文已有的具体指标。
- **改写：** 直接报告原有结果，保留对象与数值对应、比较条件、单位、方向和不确定性；没有数值时不补数值。
- **正例：** “读完曲线可知，队列长度由12降到8”→“曲线显示队列长度由12降至8”。
- **不改：** 检出率不能改成准确率；百分比不能改成百分点；中位数不能改成均值；局部改善不能写成整体领先；未显著和不利指标不能删。

## R11 精简解释、结论、建议与后续计划

- **触发：** 结论被总结套话包围，建议被多层意愿表达包裹，或后续工作绕述过长。
- **改写：** 直接陈述已有结论、建议或计划，保留“可以、建议、计划、将、尚未”的实际语义和状态。
- **正例：** “下一轮准备把逐请求轨迹也采进来”→“下一轮计划采集逐请求轨迹”。
- **不改：** “还需改进”不等于“将改进”，不能擅自添加承诺；“拟开展”不能写成“已完成”；不在结尾补机械平衡句。

## R12 把行话还原为已有的具体含义

- **触发：** “赋能、抓手、沉淀、拉通”等词遮住了原文已经说明的动作、对象或作用。
- **改写：** 使用原文足以支持的常用表达；能确定具体动作时直接写动作。
- **正例：** “让两个原本隔开的台账能够互查，以此打通信息壁垒”→“让两个台账能够相互查询”。
- **不改：** 原文没说“赋能”具体指什么时，不替作者编造机制或成效；专业定义中的行话按术语保留。

## R13 明确动作主体，精简操作说明

- **触发：** 原文给出了执行者，却用被动或多层名词结构绕述动作，或者操作说明包含多余的“完成……操作”。
- **改写：** 使用已有主体加动作；面向读者的步骤可直接使用操作动词。
- **正例：** “签名的核验工作交给网关来做”→“网关核验签名”；“The gateway performs verification of the signature.”→“The gateway verifies the signature.”
- **不改：** 执行者未知时，不为了主动句编造人或系统；学术描述不能擅自改成对读者的命令；必要的责任主体不能省略。

## R14 校准限定与因果强度

- **触发：** 多个含糊限定叠加，或者一个解释的确定程度不清楚。
- **改写：** 留下准确表达证据状态所需的限定；用原文已有原因说明不确定的内容。去掉重复限定，不去掉真实不确定性。
- **正例：** “也许大概是缓存带来的变化，但没保存命中日志”→“变化可能与缓存有关，但缺少命中日志，无法确认”。
- **不改：** 观察关联、机制猜测、模拟结果和统计显著性不能互相升级；不能新增原文未给出的不确定原因或实验条件。

## R15 区分真实对比与预设质疑

- **触发：** “不是……而是……”等结构只是在反驳文章没有提出的质疑，或结尾为了显公允空泛地补另一面。
- **改写：** 直接陈述正面的定义或主张，删除不增加信息的预设反驳和机械平衡。
- **正例：** “我们谈这个问题，绝不是想给某条路线贴标签，而是想比较资源开销”→“我们比较资源开销”。
- **不改：** “只检测、不删除”“相关不证明因果”“未检出不等于不存在”“中位数下降但尾延迟增加”会改变读者理解，必须保留真实区别。

## R16 拆解长句，合并同一信息的重复

- **触发：** 多层修饰、插入话或同义重复遮住了已有命题与关系。
- **改写：** 在需要时拆句，按已有因果、条件或比较关系组织；相邻重复可以合并，但每个独立事实、程度和边界都要留下。
- **正例：** “由于没有逐请求轨迹，贡献拆不开；这种贡献还没法分别估计”→“由于缺少逐请求轨迹，无法分别估计各项贡献”。
- **不改：** “已有少量支持”和“尚未证实”不是完全相同的信息，合并时需同时保留，例如“现有证据提供有限支持，尚不足以确认”；相反结果不能被合并掉。

## 未命中词条时的检查顺序

在显式标记保护范围以外，先找清事实与必要边界，再检查R06、R07、R15涉及的空泛话语；随后按句子结构检查R01—R05、R08—R13；最后用R14校准证据强度、用R16检查重复与长句。没有触发条件的句子保持原样，不为凑替换次数而改。

以上是内部处理规则。对用户仍按SKILL.md输出正文；只有明确存在免责声明部分时才附手动修改提醒。用户要求查看修改点时，只列具体改动，不默认重复展示长篇原文和全文改稿。
